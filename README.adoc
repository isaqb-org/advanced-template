== What is this repository?

This is the *GitHub template repository* for authoring https://isaqb.org[iSAQB] Advanced Level *curricula* in AsciiDoc.

Each real curriculum (e.g. `curriculum-flex`, `curriculum-web`) is created from this
template and then customized. The build produces PDF and HTML output in German (DE) and English (EN),
based on a set of AsciiDoc files.

== Repository structure

[cols="1,3a",options="header"]
|===
|Path |Purpose

|`docs/`
|The curriculum content. `curriculum-template.adoc` is the root structure file;
content is organized into `00a-preamble/`, `00b-basics/`, one `NN-module-block-N/`
directory per learning module, `20-examples/` and `99-references/`. Per-curriculum
configuration lives in `docs/config/setup.adoc`.

|`build.gradle` / `gradle.properties` / `settings.gradle`
|Thin project configuration. The interesting settings are the `ext` properties in
`build.gradle`: `curriculumFileName`, `languages` and `suffixTags`.

|`gradle-tools/` (submodule)
|The actual build logic. `gradle-tools/build.gradle` auto-generates one render task per
`format × language × suffixTag` combination (`pdfDE`, `htmlEN`, ...) and groups them into
`buildDocs`. The Gradle wrapper used for builds lives here.

|`pdf-theme/`, `html-theme/` (submodules)
|The iSAQB PDF theme (incl. fonts) and the HTML stylesheet applied to the output.

|`license-copyright/` (submodule)
|Shared license and copyright text included into every curriculum.

|`docs-ext/`
|[OPTIONAL] Pre-rendered PDF translations in languages other than DE/EN (see
`docs-ext/EXTERNAL_DOCUMENTS_README.adoc`).

|`.github/workflows/`
|Thin wrappers that call the reusable workflows in `isaqb-org/github-workflows`.
|===

== How to build

Prerequisite: a locally installed JDK 25 or higher. +
Clone the repository including its submodules:

[source,shell]
----
git clone git@github.com:isaqb-org/advanced-template.git --recursive
----

If you already cloned without `--recursive`:

[source,shell]
----
git submodule update --init --recursive
----

Build all languages and formats:

[source,shell]
----
./gradle-tools/gradlew buildDocs
----

The results are written to `build/`, named `<curriculumFileName>-<lang>.pdf` /
`.html`, together with an `index.html` overview page. Useful additional tasks:

[source,shell]
----
./gradle-tools/gradlew pdfDE     # build a single output (format + language)
./gradle-tools/gradlew clean     # remove the build/ directory
./gradle-tools/gradlew tasks     # list all generated render tasks
----

To change which languages or variants are produced, edit the `ext` block in
`build.gradle` (`languages`, `suffixTags`).

=== Build with Docker (no local JDK)

If you would rather not install a JDK, you can build inside a container; you only need
Docker. Clone with submodules first (the build logic and themes are needed inside the
container), then run the launcher from the repository root:

[source,shell]
----
./build-docker.sh           # buildDocs — all languages and formats
./build-docker.sh pdfDE     # a single output
----

The toolchain (Gradle + its dependencies) is downloaded once into a gitignored
`.gradle-docker/` cache, so repeat builds are fast. Output appears in `build/` exactly
as with a local build.

The image and the launcher logic live in the `gradle-tools` submodule
(`gradle-tools/docker/`); the repo-level `build-docker.sh`/`.bat` are thin wrappers that
delegate there. This way the Docker setup is upgraded centrally — bump the submodule and
every curriculum picks it up, with no per-repository changes.

== Creating a new curriculum from this template

. Click *Use this template* in the GitHub UI
. Rename `docs/curriculum-template.adoc` to match your curriculum, e.g. `docs/curriculum-flex.adoc`.
. In `build.gradle`, set `curriculumFileName` to that name *without* the `.adoc`
suffix, e.g. `curriculum-flex`.
. In `docs/config/setup.adoc`, set the curriculum metadata:
.. `:curriculum-short:` – your module abbreviation, e.g. `FLEX`.
.. `:curriculum-name:` – the full module title (set separately for DE and EN).
. Replace the README: delete this file and rename `README-curriculum.adoc` to
`README.adoc`, then fill in the placeholders. (The README you are reading describes
the *template*; `README-curriculum.adoc` is the starting point for *your* curriculum.)
. Build with `./gradle-tools/gradlew buildDocs` and review the result under
`build/index.html`.
